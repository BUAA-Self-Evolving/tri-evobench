# L1-Arena evaluation specification

The official per-turn source score is binary and deterministic. Render `{evaluation_dir}` as the stream's `evaluation` directory and `{workspace}` as the writable workspace, then execute `evaluation.primary_evaluation.source_exec_check.command`. This preserves the complete source command, including any preference clause already embedded upstream.

`evaluation.exec_check` is the task-only verifier used by the L1 `task_execution` component. When `evaluation.preference_check` is non-null, first require its declared target to exist, then run it for the `preference_adherence` component. Missing target or verifier failure scores 0. This avoids both double-counting embedded source preference commands and granting credit for helper-level "target missing, skip" behavior. L1 reporting combines task execution (0.8) and preference adherence (0.2); turns without a preference verifier use task execution weight 1.0.

All declared check IDs are mandatory success components. Therefore a task pass plus preference failure (score 0.8) is still an unsuccessful Interaction and triggers the User Simulator when budget remains; the numeric threshold alone is insufficient.

In sequential conditions, apply only `environment_updates` once before the current turn. In Reset, restore the seed and apply `reset_environment_updates` in order. For session `new`, copy the payload and upsert its `session_index` record into `sessions.json`; append updates also register a missing target session. A malformed, missing, duplicated, escaped, or late update invalidates the turn.

The embedded judge prompt is diagnostic/fallback-only. It must copy binary verifier results into corresponding check scores and must never grant credit contrary to a failed deterministic verifier. Final totals are recomputed from check components; judge-supplied totals are ignored.

If Judge repair still fails, the Turn is `evaluation_error` with score `null`; it is never converted to Agent score 0 and never triggers the User Simulator. The deterministic source result remains audit evidence only.

Derived distractors have no executable checker or tools. `response_accuracy` (weight 0.7) compares the stripped final response against `primary_evaluation.expected_response` exactly. `state_hygiene` (weight 0.3) requires zero tool calls and no workspace, session, memory, fact, skill, or standing-preference mutation. A one-turn formatting override must not influence later source turns.

Every turn uses the bounded L1 post-failure User Simulator. After a valid Agent failure with score below 0.8 and remaining budget, it emits exactly one next user message; at most two retries follow the initial Interaction. Source turns additionally require the primary source verifier to pass; distractors require their exact response and state-hygiene checks. Verifier/Judge/Simulator control-plane errors return null and never trigger the simulator. The simulator receives only public inputs plus bounded feedback, and official scoring uses the latest Interaction only.

Bounded feedback must be generated by `runtime/l1_bounded_feedback.py` from dimension-and-score pairs only and validate against `l1_bounded_feedback/1.0`. Raw checker/Judge reason text is not a projector input. Retry Interactions use `continue_with_patch`; updates are not reapplied, and state hygiene remains relative to Turn start.

Recommended reports include source task completion, preference pass rate, distractor response accuracy, distractor state-hygiene and post-noise recovery, bilingual domain/subtag breakdowns, per-stream/category macro averages, update vs non-update turns, failure streaks, cost, and update-application failures. Never mix the 46 distractor scores into the 377-turn source task completion denominator without a separately labeled aggregate.
